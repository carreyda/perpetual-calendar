# 万年历 · 单文件版

一个**零依赖、单 HTML 文件**的万年历：今日黄历、宜忌、节气、节日、休/班角标与月历总览，数据实时取自 [rili.com.cn](https://www.rili.com.cn/)（JSONP 直连，无第三方框架）。

## 在线访问

部署后地址（GitHub Pages）：

```
https://carreyda.github.io/perpetual-calendar/
```

## 功能

**首页（单日详情）**

- 公历日期与星期、农历、干支（年月日三柱）、生肖、星座
- 当前节气 + 下一个节气倒计时
- 宜 / 忌（超长自动截断为「等 N 项」）
- 节日与倒计时面板
- 右侧本月小日历：6 行 42 格、节气与节日胶囊、休/班角标、今日描边、选中红底

**月历（整月总览）**

- 本月节气与节日速览、重点日期详情、月度统计（节气数、节日日数、周末天数）
- 农历范围、生肖、月度关键词

**交互**

- 任意翻月（`‹ ›`）、点选任意日期、点标题回到今天/本月
- 搜索：`2026-11-13`、`20261113`、`2026-11`、`2026`、`11-13`、`元宵节`（节日名会在前后一年内逐月检索）
- 深链接与前进后退：`#home/2026-11-13`、`#month/2026-12/25`
- 源站不可用时有错误提示与「重新加载」按钮

## 数据来源

| 用途 | 地址 |
| --- | --- |
| 某月整月数据 | `https://www.rili.com.cn/rili/json/pc_wnl/{年}/{月}.js` |
| 某天详情数据 | `https://www.rili.com.cn/rili/json/today/{年}/{MMDD}.js` |

两个接口都是 **JSONP**（固定回调名 `jsonrun_PcWnl` / `jsonrun_Today`），且响应**不带** `Access-Control-Allow-Origin`，所以只能用 `<script src>` 加载，`fetch`/`XHR` 必被浏览器拦截。这也是本项目坚持「单个 HTML + 传统 script」形态、不引入构建工具的根本原因。

实现要点：

- 串行请求队列 + 9 秒超时；回调名用完即删，避免污染全局
- `sessionStorage` 缓存（LRU 上限 10 条）+ 内存 `Map`，来回翻月不重复请求
- 当天日数据尚未生成时，自动向前回退最多 3 天
- 远端文本（节日名、一句话描述等）一律去标签后转义输出，不直接塞 `innerHTML`
- 月数据恒为 42 格（`zhoucount = 6`），网格行数按数据动态设置，不吃日期

## 本地预览

直接双击 `index.html` 即可打开：`file://` 协议下 JSONP 同样可用，无需启动服务器。

## 部署到 GitHub Pages

仓库根目录就是站点根目录，**不需要任何构建步骤**：

1. 把本目录推到 GitHub 仓库（例如 `perpetual-calendar`）
2. 仓库 **Settings → Pages → Build and deployment**
   - Source: `Deploy from a branch`
   - Branch: `main`，目录选 `/ (root)`
3. 等几十秒，访问 `https://<用户名>.github.io/<仓库名>/`

## 已知限制

- **节日倒计时沿用源站数据**：接口 `djs[0]` 直接展示，而源站自身偶尔把春节年份写错（例如 2023-11-22 显示「春节 1172 天 / 2027年02月06日」）
- **当天日数据生成时间**：清晨前可能还没有当天文件，此时自动回退到最近可用的一天
- **导航其余 7 栏**（黄历 / 节气 / 节日 / 择吉 / 生肖 / 星座 / 历史上的今天）尚未制作，点击只有提示
- 数据版权归 rili.com.cn 所有，本项目只做前端展示
